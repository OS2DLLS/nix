# Linux-to-OS/2 Cross-Compilation Environment

This directory contains [`shell.nix`](shell.nix), the Nix development shell used as the Linux-host foundation for the OS/2 cross-compilation workspace under `/data`. It supplies host-side build tools and development dependencies, configures environment variables for the separately installed EMX toolchain, and checks that essential target tools and sysroot headers are present.

> **Important:** Nix provides the Linux host tools and dependencies. It does not provide the `i686-pc-os2-emx` cross-compiler. The EMX compiler, target sysroot, OMF tools, and Qt target installation are separate trees under `/data`.

## Entering the shell

With Nix and `nix-shell` available:

```sh
nix-shell /data/nix/shell.nix
```

The `shellHook` checks for the OS/2 C and C++ compilers, the target `stdlib.h`, the OMF archiver, and the OMF linker, and prints an error if required pieces are missing. Do not treat entering the shell by itself as proof that the cross-toolchain checks passed; inspect the hook output and verify the tools explicitly. From within the shell, inspect the configured environment with:

```sh
printf 'target: %s\nprefix: %s\nsysroot: %s\nbuild root: %s\n' \
  "$OS2EMX_TARGET" "$OS2EMX_PREFIX" "$OS2EMX_SYSROOT" "$OS2EMX_BUILD_ROOT"
printf 'CC: %s\nCXX: %s\nAR: %s\n' \
  "$OS2EMX_CC" "$OS2EMX_CXX" "$OS2EMX_AR"
```

The shell exports the target `i686-pc-os2-emx`, toolchain prefix `/data/os2emx`, sysroot `/data/os2emx/i686-pc-os2-emx`, and build root `/data/build-nix`. It also exports `OS2EMX_CMAKE_TOOLCHAIN_FILE=/data/build-nix/libolm-os2-toolchain.cmake`; this is a path expected by the environment, not a guarantee that the file exists for every project or build. Verify the relevant project toolchain file before configuring CMake.

Build outputs belong in `/data/build-nix`, not `/data/build`. Keep host tools (which execute on Linux) distinct from target tools and libraries (which produce OS/2 binaries). An OMF object/archive or successful link is not evidence that a binary has been run on OS/2.

## What the shell provides

The package list in `shell.nix` is organized into:

- Linux host build tools: GCC/binutils, Make, CMake, Ninja, Git, Autotools, parser generators, and common utilities.
- Host-side development libraries used by compiler, libolm, and Qt builds: SQLite, zlib, GMP, MPFR, MPC, ISL, libxml2, Expat, ncurses, iconv, libidn2, and libunistring.
- Optional Qt 6 host-side dependencies/modules: Qt Base, Qt Tools, Serial Port, Declarative, and Qt 5 Compatibility, including development outputs.

The shell hook preserves Nix host compiler flags and appends glibc headers with `-idirafter` to avoid breaking C++ `#include_next` header resolution. It also unsets target-related Nix compiler-wrapper variables so host compiler settings are not accidentally treated as OS/2 target settings.

## `/data` workspace layout

The following is the current top-level layout relevant to the OS/2 cross-build workspace. The source directories have Git repository links where a Git remote was configured. Build/install trees are local artifacts and generally are not source repositories.

```text
/data/
├─ nix/
│   ├─ shell.nix                     This directory's cross-build shell
│   └─ README.md                     This document
├─ build-nix/                        Build outputs, logs, host utilities, smoke tests
├─ os2emx/                           Installed EMX toolchain prefix and sysroot. Generated by cross-os2emx
├─ cross-os2emx/                     Cross-toolchain build/source workspace
├─ libc-os2/                         OS/2 libc source
├─ libcx-os2/                        OS/2 libcx source
├─ os2tk4/                           OS2 Developers Toolkit
├─ openssl-os2/                      OpenSSL OS/2 port source
├─ qt6-base-os2/                     Qt Base OS/2 source
├─ qt6-serialport-os2/               Qt Serial Port OS/2 source
├─ qt6-host/                         Linux host Qt installation/tools. Generated by qt6-base-os2.
├─ qt6-os2-install/                  OS/2 target Qt installation. Generated by qt6-base-os2.

```

## Host Qt and target Qt are separate

For Qt module cross-builds, `/data/qt6-host` supplies Linux-executable host tools and host CMake packages, while `/data/qt6-os2-install` supplies OS/2 target libraries and target CMake packages. Neither installation substitutes for the other. Keep their paths role-specific in CMake configuration and verify the selected packages in the CMake cache.

## OpenSSL paths

The shell hook exports source/build paths for the current OpenSSL OS/2 port and separate include/library paths for the older Netlabs binary fallback. Do not set a global `OPENSSL_ROOT_DIR` indiscriminately: host-side configuration may then discover target headers or libraries. The fallback is prebuilt OS/2 material, not proof that the current OpenSSL source has been built or that the fallback works with Qt's runtime TLS loader.
